# 2026-11-11: test 1, harness proof

Rows: `2026-11-11-test1.tsv`. Wolf "Test ball", HEVC 1920x1080, 30 s per
run, 20 Mbps unless the variant says otherwise. `host` is the Wolf
server; the client is the other host.

- The harness works in both directions. The 30 fps control halves every
  frame-rate field. The 5 Mbps control moves nothing (see METHOD.md).
- The client paths differ, so cross-direction numbers mix host and client
  effects. Compare only runs that share a client.
- NVIDIA client: FFmpeg `hevc_cuvid` with the SDL renderer. Vulkan
  (libplacebo) failed with "can't find any displays", and VAAPI and VDPAU
  are absent. Decode reads 19.3 ms at 60 fps and 36.0 ms at 30 fps, which
  is about one frame interval: the decoder holds a frame, so this is
  client latency rather than decode work.
- AMD client: VAAPI decode at 0.4 ms. The renderer shows 55-58 fps
  against 60 decoded, and jitter drops are 1.2-2.5%. This is client-side
  pacing, still to be explained.
- Host processing latency is empty in every run: the server does not
  report it.
- The GPU column is GFX busy, which a hardware encoder barely touches. On
  NVIDIA hosts it now samples encoder utilisation. AMD has no encoder
  sampler yet.
